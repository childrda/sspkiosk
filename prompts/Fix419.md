Build Prompt: Fix 419 Page Expired on Woken Kiosk Chromebooks
Context
sspkiosk — Laravel 12 self-service student password reset kiosk for a K-12 division (Louisa County Public Schools), FERPA-scoped. Kiosks are managed Chromebooks in ChromeOS kiosk mode.
Authorization was recently re-architected: kiosks are identified by DHCP-reserved IP via KioskNetworkService::findEnrolledKioskByIp(), and EnsureKioskWebSession resolves the kiosk by IP first on every request, re-binding the session automatically. The heartbeat (POST /kiosk/session-heartbeat) is now advisory — it feeds the admin "last seen" indicator and is not an authorization gate. Do not reintroduce it as one.
The bug
The kiosk display sleeps overnight. ChromeOS suspends or throttles the tab, so setInterval stops firing and no heartbeat is sent. The session expires (SESSION_LIFETIME=120, driver database).
In the morning a student touches the screen. The display wakes and the page is still there — same DOM, same rendered form, same CSRF token baked in from the night before. Nothing on screen indicates anything is wrong. The student types their username, clicks to continue, and the POST carries a token whose session no longer exists.
419 Page Expired, rendered as a raw framework error page, to a middle-schooler.
This is reproducible and reported from the field: "after you enter your user name and click to go to the next page I get 419. the display does turn off."
Note why the first screen looks fine — it's already-rendered HTML that needs no server round-trip. The failure surfaces on the first POST.
Why the existing heartbeat doesn't save it
resources/views/layouts/kiosk.blade.php currently ends with:
jsconst beat = () => fetch(HB_URL, {
    method: 'POST',
    headers: {'X-CSRF-TOKEN': TOKEN, 'Accept': 'application/json'},
    credentials: 'same-origin',
    keepalive: true,
}).catch(() => {});
beat();
setInterval(beat, HB_MS);
document.addEventListener('visibilitychange', () => { if (!document.hidden) beat(); });
On wake, visibilitychange does fire a beat — but that beat POSTs with the same dead CSRF token, receives a 419, and .catch(() => {}) swallows it. The heartbeat fails silently and the page keeps looking healthy. The mechanism that should detect the problem is the one hiding it.

Fix — three layers, build in this order
Layer 1 — Self-healing heartbeat (the actual fix)
The heartbeat already runs; it just needs to notice it's dead. Rewrite the script block in resources/views/layouts/kiosk.blade.php:
jsconst beat = () => fetch(HB_URL, {
    method: 'POST',
    headers: {'X-CSRF-TOKEN': TOKEN, 'Accept': 'application/json'},
    credentials: 'same-origin',
    keepalive: true,
}).then(res => {
    if (res.status === 419 || res.status === 401 || res.redirected) {
        location.reload();
    }
}).catch(() => {});
A reload issues a GET, which mints a fresh session and a fresh CSRF token. EnsureKioskWebSession resolves the kiosk by reserved IP on that GET and re-binds the session automatically — no enrollment code, no staff intervention. The kiosk repairs itself before a student touches it. (This only works because of the IP-first middleware change; do not regress it.)
Add wake/restore triggers beyond the existing visibilitychange:
jswindow.addEventListener('focus', beat);
window.addEventListener('pageshow', beat);   // bfcache restore
window.addEventListener('online', beat);
Guard against a reload loop: if a reload was already triggered, don't fire more beats. Use a module-scoped let reloading = false; flag, set it before location.reload(), and bail early from beat() when set. Without this, three listeners firing on wake can stack three reloads.
Also guard against a reload storm: if the server is down (5xx) or the kiosk record is archived, res.redirected may be true on every beat and you'd reload in a tight loop. Only reload on 419/401/redirect, and add a floor — track the last reload time in sessionStorage and refuse to reload more than once per 30 seconds.
Layer 2 — Never show a student a 419
Even with self-heal, a student can touch the screen faster than the wake-beat completes. A kiosk must never render a framework error page.
bootstrap/app.php currently has an empty withExceptions stub. Fill it:
php->withExceptions(function (Exceptions $exceptions): void {
    $exceptions->render(function (\Illuminate\Session\TokenMismatchException $e, \Illuminate\Http\Request $request) {
        if ($request->is('kiosk/*') && ! $request->expectsJson()) {
            return redirect()
                ->route('kiosk.reset.start')
                ->with('error', 'This screen timed out. Please start again.');
        }

        return null;   // fall through to default handling elsewhere
    });
})
Confirm the exact route name for the kiosk start screen — routes/kiosk.php groups reset routes under ->name('kiosk.reset.'), so verify whether the landing route is kiosk.reset.start or something else and use the real one. Do not redirect JSON/XHR requests (the heartbeat is one) — those should keep receiving a 419 status so Layer 1 can detect it and reload. If you redirect the heartbeat, you break the self-heal.
Make sure resources/views/layouts/kiosk.blade.php (or the start view) renders session('error') so the message is actually visible.
Scope the handler to kiosk/* only. Admin and Slack routes keep default behavior.
Layer 3 — Widen the margin
.env.example and config/session.php:
SESSION_LIFETIME=1440
The kiosk session holds only the kiosk_id binding — no student credentials, no PII. A 24-hour lifetime is defensible. It does not survive a weekend on its own, which is precisely why Layer 1 is the real fix and this is only margin. Document that reasoning in a comment so nobody later "hardens" it back to 120 without understanding what breaks.

Also build: idle auto-reload on the start screen
A start screen with nobody in front of it holds no state worth preserving. Reloading it periodically guarantees a live token whenever a student walks up.
Add to the kiosk layout, gated to the landing/start view only (pass a flag from the controller or use a Blade section — do not apply this to in-progress reset pages, where it would destroy a student's session mid-flow):
jslet idleTimer;
const IDLE_MS = 15 * 60 * 1000;
const resetIdle = () => {
    clearTimeout(idleTimer);
    idleTimer = setTimeout(() => location.reload(), IDLE_MS);
};
['touchstart', 'mousedown', 'keydown'].forEach(evt =>
    document.addEventListener(evt, resetIdle, { passive: true })
);
resetIdle();

Also change: don't alert on overnight kiosks
A sleeping Chromebook cannot beat — the tab is suspended and there is nothing to be done about it from the application side. So last_seen_at will show large overnight gaps by design, and the admin "last seen" indicator will report every kiosk as stale each morning.
Update AdminKioskService::isOnline() (or the view that consumes it) so staleness is only meaningful during school hours. Add config:
php// config/kiosk.php
'staleness_window' => [
    'start' => env('KIOSK_STALENESS_WINDOW_START', '07:00'),
    'end'   => env('KIOSK_STALENESS_WINDOW_END', '16:00'),
    'timezone' => env('KIOSK_STALENESS_TIMEZONE', 'America/New_York'),
],
Outside that window, render the kiosk as "Asleep" rather than "Stale" or "Offline". Do not build alerting that pages someone at 6am for every building every day — that trains staff to ignore the alert, which is worse than having none.

Tests (tests/Feature/KioskSessionExpiryTest.php)

A POST to a kiosk route with an invalid CSRF token → redirect to the start route with an error flash, not a 419 error page (regression guard for the reported bug)
A POST to kiosk/session-heartbeat with an invalid CSRF token and Accept: application/json → still returns 419, not a redirect (Layer 1 depends on this status reaching the browser)
A non-kiosk route (e.g. admin/*) with an invalid CSRF token → unchanged default behavior, no kiosk redirect
After session expiry, a fresh GET to the kiosk start route on a reserved IP re-binds the session via findEnrolledKioskByIp() and renders 200 without requiring re-enrollment (proves the self-heal path works end-to-end)
isOnline() / staleness reports "asleep" outside the configured window and "stale" inside it


Constraints

Do not reintroduce the heartbeat as an authorization gate. KIOSK_REQUIRE_ACTIVE_HEARTBEAT stays false and EnsureKioskWebSession must not regain a hasFreshHeartbeat() check.
Do not exempt kiosk routes from CSRF validation. That would "fix" the 419 by removing the protection. The fix is session freshness, not disabling the check.
Do not redirect JSON/XHR 419s — Layer 1 needs the raw status.
Do not apply idle auto-reload to in-progress reset pages.
Do not touch OfficeVerificationService, the archive/soft-delete work, roster export, label printing, or KioskNetworkService. All verified green.
Do not audit-log per heartbeat.
